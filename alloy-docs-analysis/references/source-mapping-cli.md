# Mapping doc topics to source: CLI reference pages

Path pattern in docs: `docs/sources/reference/cli/<name>.md`
Path pattern in source: `internal/alloycli/cmd_<name>.go`

Verified examples:
- Doc: `docs/sources/reference/cli/run.md` → Source: `internal/alloycli/cmd_run.go`
- Doc: `docs/sources/reference/cli/convert.md` → Source: `internal/alloycli/cmd_convert.go`
- Doc: `docs/sources/reference/cli/fmt.md` → Source: `internal/alloycli/cmd_fmt.go`
- Doc: `docs/sources/reference/cli/gql.md` → Source: `internal/alloycli/cmd_gql.go`
- Doc: `docs/sources/reference/cli/validate.md` → Source: `internal/alloycli/cmd_validate.go`
- Doc: `docs/sources/reference/cli/tools.md` → Source: `internal/alloycli/cmd_tools.go`

## Where the facts actually live in a `cmd_*.go` file

- **Flag names and help text**: registered via `pflag.FlagSet` methods
  (`StringVar`, `BoolVar`, `IntVar`, `DurationVar`, `StringSliceVar`, or `Var`
  for custom types like `featuregate.Stability`) inside a `mount*Flags`-style
  function (e.g. `mountRunFlags` in `cmd_run.go`). The flag name string is the
  second argument to each `*Var` call — that's the exact doc-facing name.
- **Default values**: set in a `new<Name>()`-style constructor's struct
  literal (e.g. `newAlloyRun()` in `cmd_run.go`), then passed as the third
  argument to the `*Var` call. Check the constructor, not just the flag
  registration line, since some flags reuse the struct field's zero value
  instead of setting an explicit default in the constructor.
- **Allowed-value enums**: for flags backed by a custom `Var` type (e.g.
  `--stability.level` uses `featuregate.Stability`), the allowed values live
  in that type's own package (`featuregate.AllowedValues()` for stability) —
  same cross-reference pattern as `references/style-consistency-frontmatter.md`'s
  frontmatter stability mapping.
- **Deprecated flags**: registered separately, often via a dedicated helper
  (e.g. `addDeprecatedFlags()` in `cmd_run.go`), not inline with the main flag
  list. **This is the single most important thing to check on any CLI
  reference page** — a doc's "Deprecated flags" section must list *every*
  flag the helper deprecates, not just the ones someone remembered to write
  down. Confirmed real gap: `cmd_run.go`'s `addDeprecatedFlags()` deprecates
  both `cluster.use-discovery-v1` and `feature.prometheus.metric-validation-scheme`,
  but `run.md`'s "Deprecated flags" section only documents the second one —
  `cluster.use-discovery-v1` is silently undocumented as deprecated right now.
  Don't assume this class of gap is rare; it's already happened at least once.

## Special case: `reference/cli/otel.md`

This page doesn't map to an `internal/alloycli/cmd_*.go` file. It documents
the `otel` subcommand, which wraps the **upstream** `otelcol.NewCommand()`
from the external `go.opentelemetry.io/collector/otelcol` module, assembled in
`collector/main_alloy.go` — a file itself marked `GENERATED CODE: DO NOT EDIT`
(generated by `collector/generate.go`). Treat this exactly like a wrapped
upstream `otelcol.*` component: flags and defaults live in the external
module, not this repo. Verify what's traceable in `collector/` and
`go.mod`/vendored source if available; flag anything requiring the external
module's internals as an open question rather than guessing.

## Special case: `reference/cli/environment-variables.md`

Split source of truth, don't treat it as one thing:
- `PPROF_MUTEX_PROFILING_PERCENT` and `PPROF_BLOCK_PROFILING_RATE` trace to
  `cmd_run.go`'s `setMutexBlockProfiling` function (verified: doc's stated
  defaults `0.1%` / `10000` match the source's fallback branches exactly).
- `GOMEMLIMIT`, `AUTOMEMLIMIT`, `AUTOMEMLIMIT_EXPERIMENT` trace to
  `internal/alloycli/automemlimit_linux.go` and
  `automemlimit_cgroups_unsupported.go`.
- `GODEBUG`, `GOGC`, `GOMAXPROCS`, `GOTRACEBACK`, `HTTP_PROXY`/`HTTPS_PROXY`/
  `NO_PROXY` are standard Go runtime/stdlib behavior, not Alloy-specific code.
  Verify these against Go's own runtime documentation (linked from the page),
  not against anything in this repo — don't go looking for Alloy source that
  isn't there.
